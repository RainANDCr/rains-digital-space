# 一个 README 能说明多少软件工程

很多小项目可以在作者电脑上运行，却无法让别人顺利开始。问题通常不在代码功能，而在缺少启动说明、目录结构和已知限制。写 README 时，我开始把读者第一次打开项目时会遇到的问题列出来：需要什么环境，怎样安装依赖，如何启动，页面有哪些入口，哪些内容仍然是计划。

## 让说明和代码保持一致

README 不是项目结束时才补的宣传文字。每次修改启动命令、目录结构或功能状态，都应该同步更新说明。否则文档越完整，误导性反而越强。清楚写出“当前已完成”和“暂未实现”，比用模糊语言制造完整感更有帮助。

## 文档也是能力证据

一份好的 README 不需要夸大项目价值。它只要让别人能复现、能理解、能继续修改，就已经体现了作者对软件交付的重视。对于还在积累经验的学生来说，这种能力同样值得展示，因为真实开发很少只有写代码这一件事。

我希望以后每个项目都从第一天开始写最小 README，让文档成为开发过程的一部分，而不是最后才想起的补丁。
