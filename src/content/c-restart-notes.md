# 重新学习 C 语言：从能运行到能解释

重新打开 C 语言时，我发现最困难的不是语法，而是承认自己并没有真正掌握。以前看过变量、指针和结构体，也完成过作业，但面对一个空文件时，常常不知道怎样组织思路。于是我把目标从“尽快做难题”改成“能够解释每一个小程序为什么这样运行”。

## 先画出数据流

写代码前，我会先写输入、处理和输出。数组里有哪些元素，循环每次改变哪个位置，函数接收什么参数，返回值代表什么，都先用普通语言说明。这样做很慢，却能发现许多原本会被编译器掩盖的混乱。代码只是把已经想清楚的步骤翻译成机器能执行的形式。

指针是最容易产生距离感的部分。我不再一上来背定义，而是画出变量、地址和指针之间的关系，再观察解引用发生了什么。只要能用一个小例子说明“指针保存的是地址，表达式访问的是地址对应的值”，后面的数组和函数参数就会逐渐连起来。

## 用错误建立记忆

编译错误、越界和未初始化变量不应该只被当成麻烦。每次遇到问题，我会记录最小复现、原本预期和实际结果，再写一句原因。这样整理几次以后，错误不再只是红色提示，而会变成可以再次检索的知识。

重新学习的过程不需要证明自己从未忘记。忘记以后还能重新搭建，才是更可靠的能力。C 语言让我看到，很多基础并不是一次学完就结束，而是会在写数据结构、调试程序和阅读系统代码时反复出现。
