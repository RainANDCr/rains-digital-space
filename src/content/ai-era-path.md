# AI 时代，普通计算机学生如何找到自己的路

AI 工具发展很快，很多计算机专业学生都会担心：如果模型可以写代码、解释概念、生成页面，自己还需要学什么？对基础并不牢固的二本学生来说，这个问题尤其现实。我不想用“只要努力就能成功”来回答，也不想把未来描述成已经确定的结论。更可行的方式，是先看清自己的起点，再建立可以验证的能力。

## 先承认基础需要重建

我在学习 C 语言、数据结构和高等数学时都有过“学过但忘了”的感觉。教材里的名词似乎熟悉，一遇到新的题目却不知道从哪里开始。这不代表之前的学习毫无意义，只说明记忆没有形成能够调用的结构。与其继续向前堆知识，不如回到最小概念：变量如何存储，循环如何改变状态，链表节点如何连接，函数为什么需要边界条件。

重建基础不能靠一次长时间突击。更有效的方式是每天处理一个小问题：手写一个数据结构操作，解释一道极限题的每一步，读懂一段简短代码后再不看答案重写。过程会慢，但每次都能留下可检查的结果。AI 可以帮助我生成例子或指出遗漏，却不能替我确认是否真的理解。

## 把 AI 当成讨论对象

使用大语言模型时，我会把它当作一个需要被核对的讨论对象，而不是自动正确的老师。先自己写出思路，再让模型提供不同解法；看到代码后，逐行说明输入、输出和边界；如果模型引用了一个结论，就回到教材、官方文档或可运行的实验中验证。

这种方法的重点不是拒绝工具，而是保留判断权。模型能很快给出一份看似完整的答案，却不一定知道课程要求、项目限制和我的真实基础。只有把问题拆小、提供上下文、检查结果，工具才会变成学习的加速器，而不是新的依赖。

## 用项目证明理解

项目不需要一开始就做成大型平台。一个能运行的学习计划工具、一个有清楚 README 的小型前端页面、一个记录数据结构操作的可视化实验，都可以成为能力证据。关键是把需求范围写清楚，保留调试过程，说明哪些地方已经完成、哪些仍然计划中。

项目也会暴露知识缺口。页面出现状态错误时，需要理解 React 的数据流；接口结果异常时，需要知道如何定位输入和输出；性能变慢时，需要思考数据结构和渲染方式。这样的反馈比单纯刷教程更具体，也更容易转化为下一轮学习计划。

## 选择适合自己的竞争方式

AI 时代并不意味着每个人都必须追逐最热门的模型岗位。对普通学生来说，稳定补齐基础、积累可展示的作品、练习沟通和文档能力，同样是现实的路线。考研可以改善学历平台，项目可以证明动手能力，英语和阅读能力可以扩大资料范围，它们彼此支持，而不是互相排斥。

我还没有一份最终答案，但可以先把下一步做具体：本学期保证课程不挂科，补回 C 语言与数据结构的核心概念，持续练习数学和英语听力，再用小项目验证学习成果。方向会在行动中调整，而不是在等待确定感时自动出现。

## 能力要能被别人看懂

在求职或申请进一步学习时，别人无法只通过“我很努力”判断能力。需要把努力转化成可阅读的证据：一个能启动的项目、一份清楚的 README、一段解释取舍的技术记录，或者一次对错误的完整复盘。作品不一定复杂，但要能说明我理解了什么、遇到什么问题、如何验证自己的修复。

这也是我使用个人网站的原因。它不是把所有经历包装成简历，而是给学习过程留下连续的上下文。读者可以看到一篇基础笔记、一项小项目和后续的改进之间有什么关系。这样的记录也会反过来约束自己：如果描述不清楚，通常说明理解还不够清楚。

## 从小规模协作开始

开源并不只是向大型项目提交代码。先学会阅读贡献指南、理解 issue、写出可复现的问题说明，也是一种能力。可以从文档修正、示例改进和小型 bug 开始，在真实协作中练习沟通和反馈。AI 可以帮助解释陌生代码，但提交前仍需要自己理解改动的影响。

对我而言，未来的优势不一定来自掌握最多的工具，而来自能否在工具变化时保持学习能力。基础、表达、验证和协作会比某个短期流行的框架更持久。只要每天完成一点可以复查的工作，焦虑就会逐渐变成方向感。
